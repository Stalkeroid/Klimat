# Клімат кімнати

3D-дашборд температури й вологості з датчиків Xiaomi LYWSD03MMC (прошивка pvvx, BTHome).
Шлюз ESP32-C3 збирає показники по Bluetooth і надсилає їх у ThingSpeak. Ця сторінка читає канал
ThingSpeak і показує кімнату з датчиками, кільцевий графік за добу та деталі по кожному датчику.

Сайт: https://stalkeroid.github.io/Klimat/

## Як усе влаштовано

```
Датчики (BLE) ──► ESP32-C3 (шлюз, буфер у флеш) ──► ThingSpeak (канал 3579358) ──► ця сторінка
```

Під час першого відкриття на кожному пристрої сторінка просить **Read API Key** каналу і зберігає його
лише в цьому браузері (localStorage). У репозиторії ключа немає.

## Як влаштовано (Vite + Svelte 5)

Сайт зібраний з вихідного коду в `app/`. На GitHub Pages іде вже готова збірка в корені репозиторію (`index.html` + `assets/`), тож налаштування Pages не змінювались.

```
app/                       вихідний код
  index.html               HTML-оболонка (шрифти, <div id="app">)
  vite.config.js           налаштування збірки
  scripts/publish.js       копіює збірку з app/dist у корінь репозиторію
  src/
    main.js                старт: стилі + монтування App
    App.svelte             створює спільний стан (Store), складає сторінку, запускає завантаження й оновлення
    components/            кожен компонент сам вираховує свої дані ($derived) і має власні стилі (<style>)
      Header.svelte        назва + стан, перемикач дня
      Calendar.svelte      спливний календар «машини часу»
      Stage.svelte         3D-кімната: камера, обертання/зум, стіни, підказка, легенда
      Markers.svelte       мітки датчиків над 3D-якорями
      Ring.svelte          кільце статистики та його кнопки
      SensorList.svelte    список датчиків
      DetailPanel.svelte   панель вибраного датчика
      Overview.svelte      огляд (зв'язок датчиків), коли датчик не вибрано
      LiveBackground.svelte живий фон: ізотерми, стани світла й тепла, хвиля нового заміру
      DayStrip.svelte      смуга доби над шапкою: коли було світло
      SetupDialog.svelte   вікно ключа ThingSpeak / демо
    lib/
      store.svelte.js      спільний стан (Store: $state/$derived) і дії — лише «джерела правди»
      config.js            канал, датчики (назви, позиції, поля, role: 'heater')
      room.js              3D-геометрія кімнати
      utils.js             кольори шкал, форматування, дати
      data.js              ThingSpeak, архів, демо-дані, ключ
      power.js             світло за батареєю: події, відрізки доби (є / немає / невідомо)
      events.js            «як давно»
      markers.js           розрахунок положення міток і перекриттів (layoutMarkers)
      actions.js           use:wheel (зум колесом)
    styles/
      theme.css            ТЕМА: кольори, радіуси, обводки, шрифти, кольори фону й смуги доби, плашки .glass/.tile
      style.css            кілька глобальних правил (body, посилання)
index.html, assets/        готова збірка (не редагувати вручну)
```

**Реактивність:** стан у `Store` дрібний (окремі `$state` на вибір, камеру, дані тощо), а кожен компонент вираховує своє через `$derived`. Тож під час обертання кімнати змінюється тільки трансформація камери (і положення міток), а список, панель, огляд і кільце не перераховуються.

**Зміни і публікація:** правити файли в `app/src`, потім у `app/` виконати `npm install` (один раз) і `npm run build` — збірка оновить `index.html` і `assets/` у корені. Імена файлів у `assets/` містять хеш, тож кеш браузера оновлюється сам (ручні `?v=N` більше не потрібні). Локальний перегляд з автооновленням — `npm run dev`.

**Відкат:** кожна версія позначена тегом (`v1.0.0` …). Повернутися — `git checkout v1.0.0` (подивитися) або `git revert` потрібних комітів. Попередня версія без фреймворку — в історії git до тегу `v1.0.0` (комміт `a0fb801`).

## Які значення де

- **Список датчиків, маркери в кімнаті, «Зараз», центр кільця без наведення** — останній запис (реальний час).
- **Кільце за добу (24 сегменти), графік і спарклайни** — погодинні середні.
- **Кільце за годину (12 сегментів)** — фактична історія: записи кожні ~5 хв.
- **Кнопки в нижніх кутах кільця** (≥56 px на екрані): ліворуч — температура ↔ вологість (кольори вологості `HSTOPS`, `humColor`, `radH` у `app/src/lib/utils.js`), праворуч — доба ↔ година. На телефоні (≤700 px) масштаб кільця і висоту кнопок рахує `mobileRingLayout()` у `app/src/components/Ring.svelte` під фактичний розмір області: кнопки однаково віддалені від кола і від шкал (≥10 px), за потреби кільце зменшується. На ПК кнопки — у нижніх кутах кільця. Панель праворуч завжди показує температуру.
- **Закриття статистики:** тап/клік будь-де поза колом (включно з кутами навколо кола). Наведення мишею показує значення сегмента; на сенсорному екрані значення закріплюється тапом.

## Тема

Всі візуальні параметри — змінні в `app/src/styles/theme.css` (`--bg`, `--surface`, `--stroke`, `--r-lg`/`--r-md`/`--r-sm`, `--text`…). Плашки використовують клас `.glass` (непрозорий фон + обводка + світлий верхній край; розмиття свідомо не використовується — гальмує прокрутку), плитки всередині — `.tile`. Фон — живі ізотерми (`LiveBackground.svelte`, кольори `--iso-*`); вимкнути рух — `BG_ANIMATE = false` у `app/src/lib/config.js`.

## Шрифти

- **Exo 2** — головний: заголовки, назви, великі значення (`--font-display`, `--font-text`, `--font-num`).
- **JetBrains Mono** — допоміжний: дрібні технічні дані — час, осі кільця, шкали, вологість у списку, підписи маркерів (`--font-data`).

Змінні — у `app/src/styles/theme.css`. Цифри всюди табличні (однакової ширини), щоб значення не «стрибали» при оновленні.

## Світло (відключення)

Визначається за батареєю (`role: 'heater'`), бо опалення працює лише тоді, коли є світло. Лише відносні зміни, без конкретних температур — тож не залежить від того, як сильно топлять. Код — `app/src/lib/power.js`:
- за 3 заміри (≈15 хв) батарея впала на ≥ 5° — світло зникло, виросла на ≥ 5° — з'явилось (`POWER_STEP`); час події — точка зламу (останній замір «плато» перед різкою зміною);
- повільний дрейф (остигання, проблеми на ТЕЦ) стан не перемикає;
- стан переходить з попереднього дня: якщо вчора закінчилось світлом і сьогодні різких стрибків не було — світло є (і навпаки); для цього дашборд дивиться назад день за днем до першої доби з різкою зміною (до 14 днів, `priorState` у `store.svelte.js`);
- наживо: від шлюзу немає даних понад 30 хв — вважаємо, що світла немає; коли шлюз довантажить буфер, вирішує батарея;
- прогалина в історії понад 30 хв — «невідомо»; після неї — за різкою зміною через прогалину, інакше стан як до неї.

Пізніше події писатиме шлюз в окремий канал ThingSpeak (обговорюється).

**Смуга доби** (`DayStrip.svelte`) — тонка лінія над шапкою з 24 шматочків по годині: медовий — світло є, нічний синій — немає, тонкий білий пунктир — невідомо, темна частина — ще не настало, біла риска — «зараз». Показує день, вибраний у шапці. Кольори — `--pw-*` у `theme.css`.

## Живий фон

Побудований як маленька система «сутність — компоненти — системи»:
- **Лінії** (`app/src/lib/isolines.js`) — пустишки: номер і сид (`BG_SEED + номер`). З сиду детермінований генератор щоразу видає той самий набір: амплітуда (12–22 px; дві сусідні разом менші за відстань між лініями — вони ніколи не торкаються), базова швидкість (6,5–10,5 px/с), фаза і повільна зміна швидкості в часі (дві довгі хвилі з періодами в хвилини). Біжуча хвиля: лінія зсувається вправо (рахує відеокарта), а система руху кілька разів на секунду лише плавно коригує її темп.
- **Ефекти** (`app/src/lib/effects.js`) — рецепти з власними атрибутами:
  - `look` — звичайний вигляд ліній; без світла — пунктир;
  - `heat` — батарея гріє: теплі хвилі з хвостом біжать уздовж ліній і гаснуть до середини екрана; розкид `random` (у кожної лінії своя швидкість, тіло, хвіст, частота появи);
  - `pulse` — новий замір: світла хвиля фронтом через увесь екран, розкид ±8 % на лінію;
  - `outage` — ефект руху: без світла лінії плавно гальмують до зупинки (старшинство вище за звичайну зміну швидкості).
- **Відображення** (`LiveBackground.svelte`) — ефект вигляду: «вікно», що їде по екрану зі своєю швидкістю (ніколи не перескакує назад), а всередині — копія лінії, яка рухається точно як лінія (той самий момент і темп, `followTrack`); шари теплих хвиль і хвилі заміру існують лише поки потрібні.

Новий ефект = ще один рецепт у `effects.js` + умова, коли він увімкнений. Вимкнено, якщо в системі ввімкнено «зменшити рух», або `BG_ANIMATE = false`.

## Огляд (коли датчик не вибрано)

**ЗВ’ЯЗОК ДАТЧИКІВ** — коли кожен востаннє передав дані: зелений < 15 хв, жовтий < 1 год, червоний — довше; вгорі `N/4 НА ЗВ’ЯЗКУ`. В архіві — час останнього запису тієї доби.

## Панель датчика

Праворуч під списком. Заголовок — назва й період (`Сьогодні · 00:00–07:13`, архівний день або вибрана година). Кнопки в заголовку — **ті самі, що в кільці, зі спільним станом**: температура ↔ вологість і доба ↔ година; зміна тут одразу змінює кільце і навпаки. Плитки: зараз/остання, середня, мінімум і максимум (з часом HH:MM). Графік — **поточна календарна доба** 00:00–24:00 (лінія доходить до «зараз», пунктир — поточний момент) або 5-хвилинна історія години; осі з підписами: значення ліворуч, час унизу; розриви в даних > 20 хв не з’єднуються. Код і стилі — `app/src/components/DetailPanel.svelte`.

## Мітки датчиків

Рамка-приціл на точці датчика + виносна лінія + табличка (назва дрібним моно, значення Exo 2, кольорова смужка — колір температури). Завжди одного розміру й чіткі, незалежно від зуму; зона дотику ≥ 44–48 px. Якщо таблички перетинаються, задня (глибше в кімнаті) плавно стає напівпрозорою, ближча — поверх; мітки не зсуваються. Датчик, що мовчить понад 15 хв, тьмяніє.

## Історія («машина часу»)

У шапці стан стоїть поруч із назвою, а перемикач дня `‹ 13 ЛИС · ПТ ›` (сегментований блок у стилі плашок) — по центру над правою колонкою, на телефоні — по центру; натискання на дату відкриває власний календар у стилі теми (`app/src/components/Calendar.svelte`). Вибраний день показується всім дашбордом: кільце — години 00…23 цієї доби (і 5-хвилинна історія будь-якої години), список і мітки — **середні за добу**, панель — «Остання за добу», середня, мін/макс, вологість середня. Статус — `● АРХІВ` (блакитна крапка). Кольори статусів — змінні `--st-*` у `app/src/styles/theme.css`: наживо — зелений, мовчить — жовтий, немає зв’язку — червоний, архів — блакитний, демо — фіолетовий. Кнопка `›` до сьогодні повертає «наживо». Дані дня запитуються з ThingSpeak (`fetchDay()` у `app/src/lib/data.js`, параметри `start`/`end`), минулі дні кешуються. Раніше дати створення каналу перейти не можна.

## Демо-режим

У вікні ключа є посилання «Відкрити демо з випадковими даними»: воно підставляє ключ `0000000000000000`. З таким ключем (будь-яка кількість нулів) сторінка не звертається до ThingSpeak, а генерує правдоподібні дані за останні 25 год (`demoFeeds()` у `app/src/lib/data.js`; батарея в демо гаряча й остигає під час 1–2 «відключень» на добу) і щоп'ять хвилин дописує нові; для архіву — відтворювані дані на будь-який день за останні 60 днів (`demoDay()`). Назви датчиків приховані — «Датчик 1…4» (`sensorName()`), кімната та сама; у статусі `ДЕМО · ВИПАДКОВІ ДАНІ`. Вийти — «Змінити ключ ThingSpeak».

## Корисне

- **Масштаб:** колесо миші або два пальці; від 1× (повний огляд) до 2×. Масштабується лише кімната (CSS `scale` на `.scene`). Кільце статистики — окремий 2D-елемент поверх сцени (`app/src/components/Ring.svelte`, масштаб — `scale` там же) і від зуму не залежить. Камера при виборі датчика ставить його в центр, тож кільце завжди навколо нього.
- **Шкала кольорів:** 0…60 °C (`STOPS` і `rad()` у `app/src/lib/utils.js`, легенда внизу сцени в `app/src/components/Stage.svelte` — там два градієнти, температура і вологість; при зміні `STOPS`/`HSTOPS` оновіть і їх; граничні значення активного режиму підсвічуються білим, поки кільце відкрите — `lgT`/`lgH` у `app/src/components/Stage.svelte`).
- **Статус угорі праворуч** (замість підзаголовка): `● НАЖИВО · HH:MM` — останній запис молодший за 15 хв (зелена крапка); `● НЕМАЄ ДАНИХ · HH:MM` — новіших немає (жовта); `НЕМАЄ ЗВ’ЯЗКУ` — ThingSpeak недоступний (червона). HH:MM — час останнього запису; повна дата — у підказці при наведенні.
- **Перевірка локально:** `npm run dev` в `app/` (або `npm run preview` після збірки). Відкрити зібраний `index.html` просто як файл не вийде — браузер не завантажує модулі з `file://`.
